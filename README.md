# NodeSpace

NodeSpace 是一个以低操作记录为前提的个人信息空间。用户只需要写下内容；应用负责把笔记、明确关系、文件引用与结构组织成可浏览的二维视图。

它不是 Obsidian 的替代品。Markdown 与附件可以继续由 Obsidian 管理，NodeSpace 负责空间组织、跨空间导航和不同信息粒度下的观察。

## 当前产品原则

- 记录优先：标签、分类和布局选择都不是开始记录的前置条件。
- 内容与视图分离：卡片和节点是同一条内容在不同缩放与场景下的表现。
- 自动整理是默认环境：力导向、树形、星型、分组和卡片平铺是可选观察方式。
- 来源必须可辨认：用户关系、原文引用、结构关系和算法回声不能混为一谈。
- 推断不改写事实：自动生成的关系与区域只是可撤销、可忽略的视觉提案。
- 本地优先：没有本地模型时仍使用确定性的轻量文本算法；本地 embedding 只提供可替换的语义辅助。

## 数据与平台

图文件目前使用：

```text
{ nodes: [], edges: [], groups: [], settings: {} }
```

桌面端使用 Electron，移动端使用 Capacitor Android，画布由 PixiJS 8 渲染。默认采用静态语义自动整理，D3 力导向仅作为可选观察方式。

当打开的目录是 Obsidian Vault 时：

- 图专用文件夹由用户在“应用与默认值 → 资料库 → 图文件夹”中指定，新资料库默认为 `./NodeSpace`；
- 旧版本已经使用的图目录会保留，不会自动移动文件；
- Vault 中的 Markdown 和附件作为只读来源投影；
- Markdown 原文仍可回到 Obsidian 编辑。

## 开发

```bash
npm install
npm run dev
npm test
npm run build
```

项目也包含一个 MCP Server，供本地 Agent 读写图空间。详见 `mcp-server/AGENT_INSTRUCTIONS.md`。

## 边界

当前自动整理系统不是“认知核心”。它只为应用提供实用、稳定的空间表现。未来的智能架构应通过独立协议读取内容变化，并输出带来源和不确定性的表达提案，而不与具体 embedding 模型或界面布局绑定。
