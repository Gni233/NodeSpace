# NodeSpace作业说明
## 一、创造性说明：
### 1. 出发点
线性的逻辑、语言组成线性的思考，受工作记忆和注意力容量限制，我们不得不将思考留存到纸或电子笔记上。多个笔记、多个章节、一张二维平面纸上的多个部分能各自推进，形成面状的思考。但我感到现有工具仍不能充分利用二维平面辅助补足、发散线性的思考的优势，于是便想要做一个帮助超过一维的概念、关系可视化的节点网络。
### 2.结构设计
图区、文件树、操作栏、编辑栏、图区自定义、应用设置五个界面部分。
节点、边、集合三种视觉与逻辑元素。
颜色、大小、形状的视觉要素，以节点等级简化部分逻辑。
布局、主题、字体、过渡、聚焦、分屏等视觉效果。
### 3.创新性
力学模拟的节点网络的项目有许多，但我在其中似乎没有见到以笔记作用为出发点的项目。
与其他节点网络项目相比，我的创新点在于：
丰富简便的操作：选中、增删、拖拽、框选、快捷键。
可编辑性：有丰富的编辑操作、可编辑项，数据可即时同步、可持久化。
数据可拓展：节点支持多媒体，可打开多媒体框。
细致的美化：可选字体、多种主题（几乎涵盖所有部分的统一性）、集合样式、节点大小与设色方案、连线颜色粗细过渡；背景格点、多种布局、多种显示/隐藏方案；增加、删除等细节处的动画。
### 4.遇到的问题
数据结构的设计从最初就让我头疼：怎样让数据保存下来，怎样让数据变成图、怎样让图和数据表现出即时同步？
经过不断摸索调整，解决如下：
数据保存用了{ nodes: [], edges: [], groups: [], settings: {...} }三层结构，用 localStorage 存，key 前缀fg-data-{图名}，JSON 序列化就直接丢进去了。每次改数据调scheduleSave()，用 300ms 防抖批量写盘，collectSettings()在保存时收集所有 live 变量快照进 settings。最终都走同一个writeGraphData入口。
数据变成图的流程是数据→d3-force力学模拟→PixiJS渲染。loadGraphData读存储→塞进graph.nodes/edges/groups→simManager.initSim()创建d3.forceSimulation，五个力场（link/charge/center/collide/radial 外加自写的 fix-collide）把节点推到稳定位置 →draw()每帧从 simulation 读坐标更新 PixiJS sprite。固定节点直接设 fx/fy 被 d3 锁定，折叠/搜索隐藏的节点通过excludeNodeIds从 simulation 和 draw 两边过滤。
用户操作（拖拽、编辑、新建、删除）直接改内存中 graph.nodes/edges，然后 draw() 重读 simulation 坐标渲染新画面，scheduleSave() 300ms 后写盘。分屏的关键设计是分屏同文件共享 graph 对象引用而非深拷贝。

## 五、Debug记录：
由于内容过多，该记录由AI根据部分历史总结，并不求全：
1. Canvas fillStyle 使用 #000 缩写颜色在部分浏览器控制台报警告。统一使用完整 6 位十六进制颜色码。
2. Canvas 物理尺寸与逻辑尺寸不一致导致渲染模糊——devicePixelRatio > 1 时 canvas.width 不等于 CSS 宽高。通过 canvas.width / devicePixelRatio 动态获取逻辑尺寸。
3. 节点移动到图区边界外自动消失。drawNodes 中手动检查了 vMinX/vMaxX/vMinY/vMaxY 做裁剪。移除手动裁剪，让 Canvas 自带裁剪处理。
4. 坐标轴交点不是画布中心，纵轴未与最高级网格线重合，边界网格线有偏移。原点改为画布中心对齐最近网格点：Math.round((gw/2)/step)*step，网格线起始点用 Math.floor(bounds.minX / step) * step 确保覆盖整个可见区域。
5. 网格可见性/坐标轴可见性/网格间距复选框开关无效。这些值在 UI 创建时被解构捕获为常量，后续拖动滑块或勾选复选框不生效。改为通过 getter 动态获取 gridVis/axisVis/gridSp。
6. 搜索功能输入关键词后渲染器不实时更新高亮。渲染器在创建时捕获了固定的搜索参数。改为通过 getter 动态获取搜索词、字段、模式，在 drawNodes 和 drawEdges 中实时过滤/高亮。
7. UI 和渲染器在创建时通过解构捕获了 simulation、transform、selNode 等状态变量，后续这些变量被重新赋值（如 simulation 被新的力模拟实例替换），但 UI/渲染器闭包仍持有旧引用，所有操作作用在旧实例上。全部改为 getter 函数传入，每次使用时动态获取最新值。
8. initSim、updateInfo 等核心函数在调用 buildUI 时尚未定义（定义在 buildUI 之后），但 UI 按钮的 onclick 需要调用它们。通过 action 空对象中转——传给 UI 的是 () => action.initSim()，等函数定义后再 action.initSim = initSim 绑定。
9. 1914 行单文件难以维护。拆分为多个模块：renderer / simulation / hit-test / interaction / forms / data / utils + entry。
10. 编辑面板透明度滑块拖动后不实时生效。滑块修改的是 JS 变量但没有同步到 editPanel.style.opacity。改为直接修改 DOM。
11. 点击画布空白区域编辑面板不消失。clearEdInternal 只清理了内部状态没有隐藏面板 DOM。在末尾添加 display = 'none'。
12. 节点默认颜色硬编码，切主题后节点全变蓝不跟随。新节点不设 color 字段。旧数据加载时做一次迁移：去掉旧默认色。
13. 标签文本修改后画布上不更新。draw 循环中只更新了节点位置没有更新 label.text。加上 sprite.label.text = n.label || id。
14. 编辑节点名称后需要点击画布才能看到更新。Enter 键没有触发即时重绘。在 Enter 处理中强制刷新。
15. 分级快捷键更新了 node.headingLevel 但没有同步编辑面板显示值。快捷键处理中增设面板值同步。
边选择与交互
16. 边完全无法选中，点击边没反应。hitTestEdge 的命中检测逻辑被某次修改破坏——参数顺序或阈值计算有误。逐行对比 git diff 后修复命中检测。
17. 右键拖拽创建连线导致页面崩溃，所有节点消失。连线创建触发了 simulation 重启，但新边引用的节点 ID 可能还未写入 graph.edges 数组，导致 simulation 初始化时找不到节点。加 try-catch 和数据有效性检查。
18. 框选只选到边时不弹出右键菜单。只检测了 selectedNodeIds.length > 0。加 selectedEdgeIndices.length > 0 的分支判断。
19. 撤消对边操作无效。undo-redo 系统在 saveUndo() 时只深拷贝了 graph.nodes，完全忽略了 graph.edges。补上边的保存和还原。
20. 聚焦模式（hover 节点时其余变淡）不保留邻边的显示。只对节点做了透明度处理，连线全部变淡。改为聚焦时保留直接邻居节点及其连线的完整不透明度。
21. 左键拖动集合框边界时触发了右键菜单。集合框的 mousedown 事件和右键菜单的 contextmenu 事件在同一个元素上竞争。加事件类型判断，左键操作不触发右键菜单逻辑。
新建/删除/连线动画
22. 新建节点导致整张画布重启（flash）。每次新建节点都触发了 initSim() 全量重建 simulation 和所有渲染器。改为仅向 graph.nodes push 新节点后局部更新，再对单个新节点做 grow-in 动画。
23. 删除节点没有动画直接消失。加 shrink-out 动画：先缩放到 0 再移除数据和重绘。
24. 删除节点不清除邻边——节点删了边还在。在删除函数中遍历 graph.edges，清理所有引用到被删节点的边。
25. 删除动画加了但画布仍然重启。删除逻辑末尾调了 initSim() 做全量重建。改为仅 splice 数据后调 draw() 局部刷新。
26. 新建连线和删除连线也触发画布重启。与 #22 同根因——不必要的 initSim() 调用。拦截多余的 simulation 重建。
27. 连线过渡出现闪烁而非平滑淡入淡出。新边从不存在到存在没有 opacity 过渡，直接在 drawEdges 中绘制完整不透明度。改为创建时 opacity 从 0 渐变到 1。
28. 新建连线后连线两端颜色和粗细与两端节点不协调。连线统一用了默认色和默认线宽。改为根据两端节点的颜色做渐变，根据节点等级做线宽渐变。
折叠/展开系统
29. 折叠后节点仍然对周围节点施加力，导致布局漂移。隐藏节点的 fx/fy 和力参数没有被清除，simulation 仍然计算它们对全局力场的影响。将隐藏节点的 vx/vy 归零，fx/fy 设为 null。
30. 折叠后节点的色晕仍然可见，形成鬼影。drawNodes 没有检查节点的 hiddenCount 状态。在 draw 循环中跳过 hiddenCount > 0 的节点。
31. 折叠动画中连线瞬间消失而非渐隐。连线的 opacity 和节点动画没有挂钩——节点开始缩小时连线还是完全不透明，动画最后一帧突然消失。改为随节点缩放同步将连线 opacity 从 1 过渡到 0。
32. 折叠动画所有层级同时开始缩，没有父子顺序感。用单一循环对所有隐藏节点同时启动动画。改为从叶子节点向上递归，每层延迟 80ms 启动，形成从外向内逐层收缩的视觉效果。
33. 折叠时父节点出现明显位移。子节点消失后父节点的质心位置改变，力平衡被打破，父节点在 simulation 中被推走。在动画期间临时固定父节点的位置，动画完成后再释放。
34. 折叠动画完成后节点在终点处抖动。动画结束时节点的 vx/vy 仍有残余速度，simulation 继续更新位置。在动画终点专门设置 vx=vy=0。
35. 折叠后色晕动画没有跟随节点同步缩小。色晕渲染在独立的 layer 上，缩放变换只应用到了节点 container 而没应用到色晕。将色晕和节点放入同一个 container 统一缩放。
36. 展开后需要手动刷新画布才能看到节点出现。展开操作修改了 hiddenCount 但没有触发 draw()。补上 draw() 调用。
37. 展开动画节点全部挤到同一位置再散开，非常不自然。展开时所有节点都以父节点坐标为目标位置同时弹出。改为在父节点周围圆上计算均匀分布的目标位置，各节点分方向展开。
38. 折叠时父节点受子节点折叠/展开影响出现明显位移。子节点消失/出现时力平衡被打破。动画期间临时固定父节点力参数，动画完成后再释放。
网格/布局系统
39. 格点模式下节点完全无法拖拽。格点吸附在 mousemove 每帧都强制执行，覆盖了拖拽设置的 fx/fy。改为格点吸附仅在 pointerup 释放时生效，拖拽过程中自由移动。
40. 关闭网格后视觉上网格仍然显示。gridVis 在渲染器初始化时被解构为常量。改用 getter 确保每次 draw 读取最新值。
41. 固定节点之间互相重叠。格点吸附只对非固定节点处理位置，固定节点的 fx/fy 没有做去重。在固定节点间加碰撞检测，若位置重叠则微调偏移。
42. 布局参数在不同图之间串了——在图 A 设格点布局，切到图 B 再切回图 A，图 A 的格点设置丢失。布局设置保存在全局变量而非 graph.settings 中。改为存在 graph.settings.layoutMode 里，每个图独立持久化。
43. 格点布局和其他布局（如默认力导向）不能共存——互斥开关导致。改为各布局类型叠加而非互斥，格点吸附作为独立维度叠加在力导向布局上。
44. 矩形框选和集合框的顶点不吸附到格点。框选创建时直接用鼠标原始坐标，没有经过格点对齐计算。在框选坐标确定后加一次格点对齐。
45. 虚线边设为虚线后力场影响没有即时消除，需要手动刷新。线型切换只改了视觉渲染的 lineStyle 字段，没有同步更新 simulation 中对这条边的力参数。改为设置虚线后立即将对应 edge 的 force 参数设为 0 并通知 simulation。
分屏系统
46. 分屏功能完全跑不通——打开分屏后文件树和标签栏全空白。分屏创建了独立的渲染器和数据结构，但没有与主文件树和标签系统共享状态引用。整个分屏机制重写，每个 pane 持有独立的渲染上下文但共享数据引用。
47. 编辑面板在双屏时左右混乱——点击左屏节点编辑面板可能在右屏出现。编辑面板是全局单例，只根据最后一次点击更新位置。改为每屏独立编辑面板实例，各屏点击只影响自己的面板。
48. 聚焦模式在双屏时行为混乱。聚焦函数内部用了全局变量记录当前聚焦节点，两屏之间互相覆盖。改为 pane-aware 聚焦，每个 pane 维护自己的聚焦状态。
49. 恢复默认只影响左屏。恢复默认函数直接引用全局唯一的 graph 变量，只改了左边。改为 per-pane graph 引用。
50. 主题设置跨屏混乱——左屏改主题右屏也跟着变。主题 CSS 变量挂在全局 document.documentElement 上，而主题选择器也只有一个全局状态。改为 per-pane 主题状态，当前聚焦的 pane 的主题作为全局 CSS 变量来源。
51. 三个以上分屏时标签栏只显示两个，第三个及之后的标签栏不可见。tab bar 的渲染循环硬编码为遍历 [0, 1]。改为动态遍历所有 panes。
52. 新建分屏后需要点击画布才能看到新窗格。分屏创建流程没有触发 ResizeObserver 或手动 draw()。在分屏创建函数末尾加 resize + draw 调用。
53. 同一文件分两个屏打开后，第二个屏往后的节点色晕变成普通圆圈而非正常色晕效果。每个 pane 的 pixi 渲染器共享同一个 WebGL context，但色晕使用的 filter/shader 在同一 context 下重复创建时有状态污染。改为 per-pane 独立渲染上下文，或共享时做 context 状态隔离。
54. 同一文件两个屏之间操作不同步——A 屏加节点 B 屏看不到。分屏时对 graph 做了深拷贝，各屏持有完全独立的数据副本。改为同一文件的多屏共享同一个 graph 对象引用，任何修改直接反映到所有屏。
55. 同步只覆盖了节点增删，设置、主题、布局变化全部不同步。sync 函数只调了 draw() 重绘但没同步 graph.settings 等元数据。扩展为完整 graph 级别的引用共享。
56. 点击画布导致所有同文件分屏都重启。canvas click 处理中调了全局唯一的 draw() 函数，该函数会遍历所有渲染器全部重绘。改为只 draw 当前 focused 的 pane。
57. 内存飙到 2-4GB。每个分屏为同一文件创建了独立的 nodeSprites Map、独立的 force simulation 实例、独立的 pixi 渲染管线——n 个屏就是 n 倍内存。改为同文件的所有 pane 共享一套 simulation 和 nodeSprites，只各自维护 viewport 状态。
58. 分屏中拖拽右屏节点导致左屏的格点缩放跟着变。viewport 的 zoom 事件监听绑定在全局 canvas 上而非 per-pane。将 viewport 事件绑定 scope 到各自 focused pane。
59. 中间分割线拖动有 bug——右移后左侧出现空白区域，左移后右侧留下无法使用的死区。分割线的 mousemove 处理中计算新位置时没有对左右 pane 做最小宽度约束。加 min-width 限制，超出边界时停止拖动。
60. 标签栏不能随分屏焦点切换而独立切换高亮。点击右屏标签时焦点切换了但标签栏没有更新活跃状态。在焦点切换逻辑中联动标签栏状态刷新。
61. 关闭分屏中最后一个标签不关闭分屏本身。closeTab 逻辑中判断 openTabs.length === 1 时应该同时移除 split pane，但没有这个分支。补上。
62. 聚焦右屏后左屏的节点色晕全部消失。色晕渲染代码假设只有一个活跃的 pane，focus 切换时把另一个 pane 的色晕 layer 整体设为了不可见。改为 per-pane 独立的色晕可见性状态。
63. 右屏完全无法选中任何节点，只能拖动画面。canvas 的 pointer 事件处理器内部引用的 hitTest 和 simulation 变量只指向了左屏的实例。改为每个 pane 绑定各自的事件上下文。
64. 同一个文件分两个屏打开后，第二屏的节点色晕退化为普通圆圈，不是正常的色晕效果。色晕使用了 pixi 的 filter/shader，在同一 WebGL context 下创建第二个同类 filter 时发生了内部状态冲突。改为共享 context 时做状态隔离。
65. 分屏创建后 canvas 在 ResizeObserver 触发前就开始渲染，导致初始画面尺寸为 0×0。RAF 回调中 canvas 尺寸尚未被 ResizeObserver 更新就执行了 draw。改为在 draw 前检查 canvas 尺寸，若为 0 则跳过并在下一帧重试。
66. 三个分屏时布局计算错误——第一个占 1/3、第二个占 1/3 但无边界线、第三个挤占剩余空间。分割线位置计算用了固定偏移而非百分比。改为基于 pane 总数动态分配宽度百分比。
67. 切换标签到一个未打开的图时，旧图的内容仍然覆盖在画布上。切换逻辑只改了 activeTab 变量但没有清空旧渲染内容。在加载新图前先清除画布、重置渲染器状态。
68. 同一文件两屏之间的同步一度完全失效——多次尝试修复都失败。问题根因是各屏持有 graph 的深拷贝而非引用，每次"修复同步"都是在拷贝之间复制数据，一旦某个操作绕过复制逻辑就不同步。最终方案改为同文件分屏共享同一个 graph 对象引用。
69. 集合的"流体"边界模式只能形成凸包，无法表现内凹形状。边界生成算法只做了凸包计算。改为支持局部曲率反转的算法，允许边界向内凹陷。
70. 节点拖拽时加了一个近距离放大效果，但基础缩放看不到、最大放大倍率太高（2.5x）。调整为 1x~2x 范围，并只在节点间距离小于阈值时触发。
71. 布局算法切换和布局动画不同时启动——算法已经开始运算但动画延迟了 300ms 才触发，视觉上节点先是瞬移到新位置再回退做动画。把动画启动和算法启动放在同一个 tick 里。
72. "回正"按钮缩放到的中心点不是世界坐标原点。适配函数只取了当前所有节点的几何中心，而不是仿真力场的原心。改为以力场中心（0, 0）为回正目标。
73. 恢复默认设置的按钮范围过大——不仅重置了图设置，还意外覆盖了用户自定义的节点颜色和字体。恢复默认的 scope 没有做分级。拆分为两级：只重置图参数 vs 全局重置。
74. 切换到已打开过的标签正常，但切换到未打开过的图时，当前图的内容被新图覆盖而非新建标签。openTab 逻辑在标签不存在时走了覆盖当前标签的分支。加上"如果标签不存在则新建标签"的分支。
75. 新建节点后编辑面板的名称输入框没有自动获得焦点，需要手动点一下才能改名。创建编辑面板时没有对输入框调 focus()。在合适的时机补上 autofocus，同时处理 Enter 退出编辑。
